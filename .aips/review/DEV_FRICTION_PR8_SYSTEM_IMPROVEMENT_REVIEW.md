# System Improvement Review — Dev Friction PR8: Worktree Shared Intelligence

- **Appropriateness:** Suitable. Every new worktree paid the full initialization cost, and copied stores were reported STALE for an identity change that had no bearing on the content.
- **User problem:** Claude Code creates many agent worktrees. Each began with `MISSING` Intelligence, re-walked the repository, and about 200 stores accumulated in the user config directory. Copied or moved stores were marked STALE by `worktree_identity_changed` even when the content matched the repository.
- **Proposed solution:** Seed a new worktree's external store from the READY store of the same repository, copy-on-write, with a deterministic source order and a strict same-repository proof. Record provenance, and treat the identity change as an observation only when that provenance proves it. Fall back to normal initialization with a diagnostic on any refusal or error.
- **Reuse / lower-layer alternative:** Reuses the existing store layout, `repository_identity` (same `repository_id` across worktrees of one repository), `git worktree list`, the freshness engine, atomic writes and the GC orphan rule. No new storage, daemon, cache or dependency.
- **Security / reliability:** The source is only read and is never locked or written. Only an allowlist of Intelligence artifacts is copied; retrieval metadata, reviews, lock files and notes are excluded. Symlinks anywhere in the source refuse the seed, and the projects directory and store paths are confined. The source must be a worktree git lists with the same common git directory, and it must carry the same AIPS repository identity, so a store from another repository or a forged identity is never copied. Copies go to a staging directory and are renamed into place, so no partial store is visible. Stale checks stay in force for every changed watched path; a copied store is never treated as proven current without the new worktree's freshness check.
- **Compatibility:** Additive `provenance` block and two new observation names; no schema or reason code change. Existing stores are never overwritten (seeding requires an absent or empty target). `aips intelligence gc` is unchanged because a seeded store records its own worktree root.
- **Constitution impact:** NO. No authority, Human approval, privacy, publication or content-safety rule changes. Secret-bearing or retrieval-cache artifacts are not copied.
- **Recommendation:** Adopt as PR8 of the approved plan; default on for the EPHEMERAL store mode only.
- **Additional optimization candidates:** Sharing the retrieval index across worktrees (it is keyed per workspace in the cache home) and seeding ATTACHED `.ai` stores are left out of this PR; the retrieval index is the next largest cost for a new worktree.
