# v0.48.0 — Verifiable Governance Audit Chain

## System Improvement Review
Appropriateness: ADOPT with modification.
User problem: long-term offline-verifiable provenance for approval, security, publication and production evidence.
Proposed solution: HMAC chained audit log.
Existing coverage: Approval Record SHA-256 scope binding, APPROVAL_STALE, SAL evidence, Release Readiness and product audit logging.
Reuse: extend existing Enforceable Governance; no new Role, Skill, Capability ID or approval gate.
Security: hash chain + optional HMAC + optional Ed25519; keys stay outside Git/artifacts/prompts. Tail-truncation resistance requires an externally retained expected chain head/event count or equivalent checkpoint anchor.
Backward compatibility: additive and credential-free by default.
Constitution impact: NO; Human authority remains unchanged.
Architecture: governance-security surface and detailed Mermaid/Human docs affected; top-level Human SVG stays accurate because Governance + Evidence topology is unchanged.

## Core Change Scope

In scope: deterministic JSONL ledger, canonical SHA-256 event/chain hashes, optional HMAC, optional Ed25519 checkpoint through OpenSSL, offline verify, fail-closed authenticated-history append, SAL/Release guidance, Scenario 158 and lifecycle evidence.

Out of scope: new approval authority, blockchain/timestamp service, remote ledger service, mandatory baseline secret, runtime hook auto-capture, new Role/Skill/Capability ID, VERSION/CHANGELOG finalization before validation.

Data/migration: no existing data migration; new additive ledger v1.
Rollback: remove new protocol/script/template/tests and references; existing Governance Guard remains intact.
Secret impact: no baseline secret; optional HMAC env and runtime Ed25519 key files only.
Approval: current Human request explicitly approved implementing the recommended v0.48.0 direction.
