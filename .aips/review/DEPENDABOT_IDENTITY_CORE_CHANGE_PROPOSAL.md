# Git Identity Metadata: GitHub App Bot Author and Dependabot Sign-off

All addresses in this document are written with `\x40` or described in words, so the proposal itself passes the
`pii.email.v2` staged-blob scan.

## Purpose

Let commits generated by GitHub's Dependabot pass the `git_identity` and `content_safety.commit_messages` gates
without weakening PII detection, without a PII exception record and without granting any authority to a bot identity.

## Why this is a core change

Both gates sit on the publication path (`publish_preflight.py run` in the CI janitor job and local preflight).
`config/git-publication.yaml` and `scripts/publish_preflight.py` are protected publication-preflight surfaces, and the
change alters which Git metadata the content-safety gate scans as PII.

### Root cause 1 (identity)

```yaml
- '^(?:[0-9]+\+)?[A-Za-z0-9-]+\x40users\.noreply\.github\.com$'
```

The local part cannot contain `[` or `]`, so the GitHub App bot form `<id>+<slug>[bot]` is rejected.

### Root cause 2 (commit message)

`content_safety_plan` scans `git log --format=%B base..head` as one `git_commit` payload. The Dependabot sign-off address
is a regular email match and `pii.email.v2` blocks it. The commit Hook (`governance_guard`) already replaces
`Co-Authored-By` trailer emails with a placeholder before the PII scan, but the preflight does not, and neither path
knows `Signed-off-by`.

## Design

### Option A (recommended): Git identity metadata policy

1. **Bot author format** — new key `identity.allowed_bot_author_patterns` in `config/git-publication.yaml`:

   ```yaml
   allowed_bot_author_patterns:
     - '^[0-9]+\+[A-Za-z0-9](?:[A-Za-z0-9-]*[A-Za-z0-9])?\[bot\]\x40users\.noreply\.github\.com$'
   ```

   - Numeric ID is mandatory (the existing human pattern makes it optional); `[bot]` is literal; the slug follows GitHub
     login character rules; `fullmatch`, no other domain.
   - Applied only to the **author** field in `commit_identity_plan`. The committer field and the local
     `configured_identity_plan` keep the existing patterns only.

2. **Trailer identity** — new key `identity.trailer_identities` (exact tuples, no wildcards):

   ```yaml
   trailer_identities:
     - key: Signed-off-by
       name: dependabot[bot]
       email_pattern: '^support\x40github\.com$'
       requires_author_slug: dependabot
   ```

   In `content_safety_plan`, messages are scanned per commit (`git log --format=%B -1 <sha>` over
   `rev-list base..head`). For each commit, a trailer line is replaced by `Signed-off-by: dependabot[bot]
   <git-identity-metadata>` before `safe_emit` **only when all hold**:

   - it is in the final paragraph, and every line of that paragraph is a Git trailer (`Token: value`);
   - the line fullmatches `^Signed-off-by: dependabot\[bot\] <(?P<email>[^<>\s]+)>$` (exact key spelling, single
     spaces, no extra text);
   - the email fullmatches `email_pattern` (case-sensitive, ASCII only);
   - that commit's author email fullmatches `allowed_bot_author_patterns` with slug `dependabot`.

   Any other line — a personal `Signed-off-by`, a second address on the line, the same address in the body, the same
   trailer under a non-bot author — is scanned exactly as today and still blocks.

3. Per-commit scanning keeps findings line-accurate and prevents one commit's trailer block from covering another's.
   The `explicit_commit_message`, PR body, diff and secret-scan checks are unchanged.

### Option B (stricter variant of A): also require `PURE_DEPENDENCY_UPDATE`

Accept the bot author and trailer only when `pure_dependency_update(base, head)` is `PURE`. All eight current PRs
qualify. Rejected as the default because neither relaxation grants authority or exposes personal data (see Abuse
analysis), and `pure_dependency_update` is deliberately content-only ("labels, authors and commit messages are never
consulted"); coupling it to identity adds a cross-gate dependency without a security gain. Can be selected if preferred.

### Option C (rejected): trust only GitHub-verified bot signatures

Would query the GitHub commit verification API in the gate. Rejected: the current heads are unsigned after the local
rebase (`%G? = N`), the gate must stay deterministic and offline-capable, and signature verification answers "who
created this commit", which this privacy gate does not control.

### Option D (no relaxation)

Keep both gates. Each Dependabot update is recreated manually under the maintainer's identity with the sign-off
removed. Zero gate change, but every bump becomes manual, the PR loses Dependabot tracking (Dependabot closes or
recreates it), and the automation stays unusable. To our knowledge Dependabot offers no option to drop its sign-off.

### Option E (rejected): change `pii.email` to ignore Git trailers

DCO `Signed-off-by` and `Co-authored-by` trailers normally carry personal addresses; this is real PII.

### Option F (rejected): content-safety exception record

`config/content-safety-exceptions.yaml` rejects every `pii.*` rule ID by design (Plan47). Not changed.

## Abuse analysis

Anyone can write any author and any trailer into a commit. The design is safe because it does not rely on authenticity:

| Forged element | What the forger gains | Why acceptable |
|---|---|---|
| Bot author format | Commit passes `git_identity` | The gate is a privacy control, not authentication. Today any person's numeric noreply already passes; a `[bot]` noreply is equally non-personal. Diff content safety, secret scan, required checks and human review/merge are unchanged. |
| Dependabot sign-off | One public organizational GitHub address in a fixed position passes | Exposes no personal data. Requires the bot author too; any other address on the line or elsewhere still blocks. |
| Both, plus a malicious diff | Nothing extra | No gate derives authority, risk class, documentation exemption or merge permission from the author or message (`automatic_merge_authorized` stays false; Human merge authority unchanged). |

Smuggling attempts that must stay BLOCKED: second address after the trailer, trailer in the body, extra non-trailer
line in the final paragraph, Unicode confusables or fullwidth `＠`, upper-case domain, `Co-authored-by` key, name not
`dependabot[bot]`, author not a bot or a different bot slug, bot address in committer or local `user.email`.

### Trade-off: relax only these two conditions vs. no relaxation

| | Option A | Option D |
|---|---|---|
| PII detection | Unchanged except one exact public address | Unchanged |
| Authenticity | Not claimed (same as today) | Not claimed |
| Maintenance | Dependabot PRs pass after rebase | Manual recreation per update |
| Policy surface | +2 config entries, empty list = today's behavior | None |

## Proposed Scope

### In scope

- `config/git-publication.yaml`: add `identity.allowed_bot_author_patterns` and `identity.trailer_identities` exactly as
  above; validate types on load and fail closed (BLOCKED) on malformed entries.
- `scripts/publish_preflight.py`: author-only bot format in `commit_identity_plan`; per-commit message scan with exact
  trailer-identity masking in `content_safety_plan`.

### Out of scope

- `scripts/content_safety.py`, `pii.email.v2`, `config/content-safety.yaml`, `config/content-safety-exceptions.yaml`,
  `tests/test_content_safety.py`, `config/integration-gate.yaml`.
- The commit Hook (`governance_guard.py`) — Dependabot commits are never created through the local Hook.
- #337 / #339 Core Change Test Matrix, branch protection, `--admin`, auto-merge, rebasing or merging the Dependabot PRs.

### Observed but excluded (follow-up candidates, need separate decisions)

- The commit Hook accepts any `Co-Authored-By` trailer address, while the preflight blocks all of them. The two paths
  are inconsistent; a later change could apply the same exact identity policy to both.
- CI runs the PR head's own copy of `publish_preflight.py` and its config, so each Dependabot PR must be rebased onto the
  merged change before it can pass.

## Risks

- Pattern too wide: limited by mandatory numeric ID, literal `[bot]`, author-field only, and the negative corpus.
- Trailer grammar parsing errors: limited by exact-line fullmatch, final-paragraph-only and per-commit scanning.
- Documentation placement churn (seen on the #350 branch): mitigate by previewing `docs-impact --require-complete`
  before each commit and keeping additions in allowed H2 sections; stop and report if closure grows beyond the 14 files.
- Dependabot changes its sign-off format: the change fails closed (blocked again); update the tuple by a new approval.
