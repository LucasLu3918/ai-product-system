# v0.51.0 — Parallel Runtime Resource Isolation

## System Improvement Review

Appropriateness: ADOPT with bounded scope.
Problem: AIPS already isolates parallel writers with Git worktrees and Change Boundary locks, but local dev/test processes still share host TCP ports and may collide.
Reuse: extend the existing Execution Isolation + Deterministic Scheduler surfaces. Do not add a Port Manager Role, Skill, Capability ID, approval gate, container platform or second workspace ownership system.
Recommended solution: add repository-scoped atomic TCP port leases, host availability probing, runtime environment manifests, independent release/reconciliation, and bounded address-in-use reallocation. Scheduler validates/propagates requests but does not allocate host resources.
Determinism: candidate order is deterministic from repository/isolation/resource identity. The selected numeric port may differ by host because current host occupancy is an explicit runtime input.
Safety: leases grant no network/resource authorization beyond port coordination. Dirty worktree preservation remains fail-closed. Orphan reconciliation only releases leases whose isolation is not ACTIVE.
Compatibility: additive CLI/task-graph fields; existing worktrees/task graphs without runtime requests keep prior behavior.
Constitution impact: NO.
Architecture impact: existing harness-runtime / Execution Isolation surface and deterministic scheduler contract are affected; no new top-level subsystem.

## Core Change Scope

In scope:
- TCP port lease registry outside project source;
- atomic cross-process allocation lock;
- preferred port + deterministic fallback candidate ordering;
- IPv4/IPv6 host bind availability probe;
- canonical AIPS_PORT environment manifest and explicit aliases;
- runtime-lease / runtime-reallocate / runtime-release / runtime-reconcile;
- clean isolation removal releases runtime leases;
- Task Graph runtime port metadata + Scheduler validation/dispatch handoff;
- Scenario 161 lifecycle evidence and documentation/architecture synchronization.

Out of scope:
- UDP;
- Docker/network namespace creation;
- database/schema/Redis/GPU/resource quota leasing;
- automatic process start/stop;
- scanning/killing unknown processes;
- automatic release of an ACTIVE-but-idle lease;
- new Role, Skill, Capability ID or Approval Gate;
- external Agent/provider credential requirement;
- VERSION/CHANGELOG finalization before feature and protected-main validation.

Rollback: remove v0.51 runtime lease fields/commands/tests/docs; existing v0.50 worktree and Scheduler behavior remains valid for task graphs without runtime requests.
Human approval: the current request explicitly authorizes the recommended implementation and Git update flow.
