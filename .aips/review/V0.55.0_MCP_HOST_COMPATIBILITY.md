# v0.55.0 — MCP Host Compatibility

## Core Change Proposal

Purpose: make canonical AIPS Roles, Skills, selected protocols, and review workflows usable by MCP hosts that expose Tools but not Resources or Prompts, while preserving the richer MCP surface for capable hosts.

In scope:
- additive read-only capability catalog/read/workflow Tools;
- truthful MCP Tool annotations;
- review-only Cursor, Windsurf, GitHub Copilot CLI, Amp, Codex, and generic configuration output;
- explicit MCP-only versus native-adapter selection policy;
- Scenario 164 lifecycle/contracts and synchronized documentation.

Out of scope:
- automatic client configuration mutation;
- remote HTTP/OAuth/hosted service;
- provider-model execution inside the gateway;
- replacing native adapters or adding Windsurf hooks;
- protected Human approval, Git publication, merge, release, production, or host-native enforcement authority.

Compatibility: additive; existing Resources, Prompts, Tools, client selectors, stdio transport, and native adapters remain available.

Security: all exposed tools are side-effect-free and declare read-only/non-destructive/closed-world hints. Canonical capability reads remain index/allowlist bound. Project tools remain confined to `AIPS_MCP_WORKSPACE`.

Architecture: extend the existing MCP access plane rather than introduce a new Capability ID, Role, Skill, orchestration system, or adapter. Tool-only wrappers reuse the same canonical indexes and prompt renderer.

Constitution impact: NO. Protected Human Authority and publication/release boundaries remain unchanged.

Human approval: the user explicitly approved the expanded tool-only compatibility facade and requested full verification before publication to `origin/main`.
