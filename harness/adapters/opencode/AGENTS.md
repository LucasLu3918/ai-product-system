# AIPS Global Turn Harness

The read-only `aips project diagnose <path>` command reports configured Runtime status and static MCP capability only; it does not prove this Host delivered Context or executed a Hook/Tool. Keep unsupported effects UNVERIFIED until native acceptance evidence exists.

For creative execution, invoke the structured tool only for an explicit create/modify request. `prepare` creates a versioned Character Profile, Style Profile, README and draft Bundle under a project-relative EPHEMERAL scope, uses create-only writes, and cannot launch a generator; require a READY Bundle preflight before explicit execution. Shell diagnostics remain limited to the fixed AIPS read-only allowlist.

For software/product/project work, resolve the current Turn Context before analysis or mutation:

`aips intelligence context --runtime opencode --project "$PWD" --prompt "<current user request>"`

Follow the returned `harness/BOOTSTRAP.md`, `SYSTEM_CORE.md` and selected canonical protocol paths progressively. Preserve existing project and runtime instructions. Resolve Project Intelligence and Change Impact before existing-project mutations, then verify affected inputs, outputs, data, events and consumers.

Discover AIPS native Skills on demand. Generated Skills, Commands and the V2 plugin are projections; their canonical source paths point into the installed AIPS system. Preserve the user-selected model and all Human approval, publication, merge and release boundaries. Resolve Context and native write decisions from the active Session directory, not the plugin setup location. Context is capped at 12,000 bytes. In EPHEMERAL creative sessions, use the private external read-only asset profile and suggest new versioned outputs without overwriting existing assets. L1 is limited to a new confined creative asset in a non-Git workspace; existing project writes use L2 readiness. Shell uses a small effect-aware read-only policy; it is not a process sandbox. External actions remain behind existing Human gates. MCP/custom tools and out-of-process writes are not covered. `aips harness trace` exposes a bounded event summary without prompts or file contents. Plugin setup, host discovery, Context delivery and permission enforcement have separate evidence states; successful installation does not prove them on a new host. Overall governance remains ADVISORY because Shell subprocesses, MCP/custom tools and out-of-process writes are outside the guard.

Creative tool lifecycle: `discover` and `preflight` are read-only and do not require a create intent; `prepare`, `configure` and `execute` use bounded user-only request authorization. Normalize native Context envelopes before extracting user text. `configure` creates an allowlisted versioned Bundle without modifying its source. A cancelled, planning or unrelated request revokes continuation; an unanchored short reply grants no authority. For detailed raster artwork, never silently substitute SVG. Load creative-calibration, visual-direction and visual-quality-review at their respective stages and distinguish execution, raster-container validity, visual review and user acceptance.

On OpenCode V2, the custom creative tool is exposed in the Code Mode catalog as `tools.creative_execution`; call that exact catalog signature through the native `execute` tool. Use active-dispatch user messages bound to the Session root; native session snapshots may use `type: user` and `text` rather than `role` and `parts`.

For local Z-Image Turbo generation, use the shared creative_execution capability mapping to the dedicated MFLUX command or the fixed ComfyUI split-loader workflow; the latter verifies local UNET, Qwen `lumina2` CLIP and VAE files and strips prompt-bearing PNG text metadata. Edit and other Z-Image variants remain unsupported.
