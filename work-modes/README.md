# Work Modes

Choose one primary mode from the user's intent. Add a second mode only when the task genuinely crosses boundaries.

| Mode | Use when |
|---|---|
| Product Creation | creating a new product from incomplete or early-stage intent |
| Design | producing UX/UI/visual concepts without unnecessary engineering work |
| Engineering Change | modifying an existing codebase or API |
| Performance Optimization | measuring and improving latency, throughput or resource use |
| Delivery Planning | turning an existing product plan into an execution sequence |
| Cost Analysis | estimating infrastructure/capacity/provider cost |
| Research | investigating options or risk without implementing changes |
| Review | independently reviewing code, architecture, design or plans |
| Incident | diagnosing/restoring a production issue |

Architecture, security, testing and operations are usually roles/skills inside these modes rather than separate top-level modes unless the user's intent is specifically an audit/review.
