# Scenario 221 — Dependency Update Risk Classification

Dependency update classification maps known packages and GitHub Actions to an explicit risk class and recommended validation plan. Unknown packages fail closed to `UNCLASSIFIED` / `HIGH` and require human review. Semantic runtime updates require retrieval regression evaluation and a semantic trial. Classification is advisory evidence only: dependency updates and policy changes never auto-merge or gain automatic approval.

Pure dependency update documentation exemption: `scripts/dependency_impact.py classify-diff` (and the shared `pure_dependency_update` predicate used by Documentation Impact, Documentation Placement and Documentation Sync) returns `PURE_DEPENDENCY_UPDATE` only when every changed file is an allowlisted dependency manifest modified in place and every changed line pair is either a full-SHA pinned `uses:` reference with the same action identity and a non-decreasing version comment, or an exact `name==version` pip pin with a strictly higher numeric version. Any other line, path, file mode, untracked file, planned path, size-limit overflow, downgrade, unpinned reference, Git error or classifier block yields `NOT_PURE` and the full documentation rules. The exemption suppresses documentation requirements only; it records per-item classification and `human_review_required`, keeps `automatic_merge_authorized: false`, and never changes secret scanning, content safety, the Core Change Test Matrix, the Integration Gate, required checks or Human merge approval.

Repository preflight and action pins: every diff-based Documentation Sync consumer (`scripts/repository_preflight.py`, the documentation sync contracts and the `scripts/documentation_sync.py` CLI) evaluates through `documentation_sync.evaluate_candidate`, which applies the same `pure_dependency_update` predicate and equality guard as Documentation Impact and Placement. Validation contracts check GitHub Action pins with `dependency_impact.require_pinned_action` instead of copied SHA literals: the exact action identity, a full 40-hex commit SHA for every reference, a version comment at or above the reviewed floor, and one shared SHA across paired evolution workflows. The evolution configs name `action: openai/codex-action`; the commit lives only in the workflows. Human review still confirms that a moved SHA is the upstream tag commit.

Path normalization: Documentation Sync removes only a single leading `./` from changed paths; hidden directories keep their leading dot, so `.github/**` triggers (Technology Guide and rule-specific workflow paths) are enforced for workflow edits. A workflow-only Human change without the mapped documents fails; the same change as a verified pure dependency update remains exempt through `evaluate_candidate`.
