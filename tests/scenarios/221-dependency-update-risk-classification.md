# Scenario 221 — Dependency Update Risk Classification

Dependency update classification maps known packages and GitHub Actions to an explicit risk class and recommended validation plan. Unknown packages fail closed to UNCLASSIFIED / HIGH and require Human review. Semantic runtime updates require retrieval regression evaluation and a semantic trial. Classification is advisory evidence only: dependency updates and policy changes never auto-merge or gain automatic approval.

Mixed-candidate documentation filtering: scripts/dependency_impact.py verifies each changed dependency-manifest file's complete diff and reports both the full sorted candidate_files set and its verified_files subset. Documentation Impact, Documentation Placement and Documentation Sync may omit verified pin-only paths from documentation trigger matching only when the consumer's complete candidate path set exactly matches the report. The overall PURE_DEPENDENCY_UPDATE status remains reserved for candidates where every changed file is verified.

Any mixed semantic hunk in a dependency file leaves that whole file in documentation matching. Unknown paths, path or mode changes, untracked files, planned paths, malformed or non-ASCII changes, invalid or unpinned action references, identity changes, downgrades, unknown dependencies, size-limit overflow, policy errors and Git/parser errors fail closed; an error affecting one path never marks that path verified. All other candidate paths continue through the complete existing Documentation Impact, Placement and Sync rules.

The report remains bound to the full candidate path set and diff hash. The exemption changes documentation trigger matching only; per-dependency Human review, secret scanning, content safety, the Core Change Test Matrix, Integration Gate, CI/Required Checks and Human merge approval remain mandatory. automatic_merge_authorized stays false, and policy changes are never authorized automatically.

Every diff-based Documentation Sync consumer (scripts/repository_preflight.py, the sync contracts and the scripts/documentation_sync.py CLI) uses documentation_sync.evaluate_candidate and the same full-candidate binding as Documentation Impact and Placement. Action-pin contracts still require exact action identity, a full 40-hex commit SHA, a version comment at or above the reviewed floor, a shared SHA across paired workflows when specified, and Human confirmation that the SHA is the upstream tag commit. Path normalization removes only one leading ./; hidden .github/** paths retain their leading dot and continue to trigger workflow rules unless verified as pin-only.
