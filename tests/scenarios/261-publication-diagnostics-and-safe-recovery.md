# Scenario 261: Publication diagnostics and safe recovery

Given an explicit candidate worktree, when AIPS observes GitHub branch, effective-rule, ruleset, and classic branch-protection endpoints, then it records each endpoint, HTTP status, bounded sanitized error and evidence level. A branch-protection 404 is `NOT_CONFIGURED` only when the branch itself exists; if `branch.protected` is true while classic policy is permission-hidden, policy state is `UNKNOWN_PERMISSION`; only complete cross-checked evidence can establish an unconfigured policy.

Given a dirty candidate, when publication validation or `aips publish doctor --worktree-details` inspects it, then staged, modified, deleted, and untracked repository-relative paths are reported without reading file contents or changing the worktree. Unknown files are preserved for Human review.

Given any protected publication refusal, when AIPS returns its diagnostic, then it includes a stable reason code, phase, blocker source, retryability, safe recovery mode, candidate SHA when verified, timestamp, and diagnostic ID; raw stderr, headers, credentials, and exception text are not emitted. Push, PR creation, checks, and merge failures remain attributed to their own phases.

Given a publication command uses a shell pipeline, multiple commands, an unsupported wrapper, or `git push -u`, when read-only diagnosis rejects it, then the stable top-level `COMMAND_FORM_UNSUPPORTED` remains compatible and a bounded `detail_code` identifies the form with a safe recovery step. The diagnostic never includes the literal command and pipelines remain blocked.

Given Claude Code emits `PostToolUseFailure` for a started Bash tool, when AIPS receives the failure event, then it reports `phase: native_tool_execution`, `execution_status: FAILED`, a fixed safe category, and the actual exit code when it can parse one. It omits the native error text, command, paths and secrets; it does not retry or authorize the operation. A PreToolUse denial remains `execution_status: NOT_EXECUTED` and never enters this failure path.

Given a known publication rejection, when `PublicationError` is created, then its call site supplies an explicit stable reason code. An unclassified failure returns `INTERNAL_DIAGNOSTIC_GAP` and a safe error class; the class is included in the Claude Code denial context and optional redacted ledger only after allowlist validation. A push target that differs from the current engineering branch returns `PUSH_TARGET_BRANCH_MISMATCH`. Both retain phase, blocking rule, safe recovery guidance, and Traditional Chinese detail without exposing exception text.

Given Claude Code v2.1.295 or later, when AIPS installs its managed PreToolUse publication guard, then it sets `onFailure: "block"` for that guard. Older or unknown versions omit the unsupported setting and report that host-level blocking on hook failure is unavailable; the UserPromptSubmit context hook and PostToolUseFailure diagnostic hook remain independent of that policy.

Given Prepare and PreToolUse inspect the same candidate, when their observations are compared, then they expose the same allowlisted worktree ID, candidate SHA, full target ref, publication mode, AIPS version/revision, and binding fingerprint. A changed worktree, SHA, target or runtime version is visible as drift; the fingerprint is observational only and grants no authority.

Given `aips publish prepare` returns `PLANNED` with `next_step: PUSH`, then authorization remains `NOT_GRANTED` and execution remains `NOT_EXECUTED`. `AWAITING_AUTHORITY` identifies missing Human grant; a Hook `AUTHORIZED` status means AIPS allowed the tool while Host decision remains unevaluated and execution has not started. `EXECUTED` is reserved for an observed completed native action.

Given `AIPS_GOVERNANCE_AUDIT_LEDGER` is configured, when a Prepare, Hook, or Doctor diagnostic has a Diagnostic ID, then the system may append only allowlisted redacted fields to that existing hash-chained ledger, and `aips publish diagnose --diagnostic-id <UUID>` returns the matching event only after chain verification. Unset configuration returns `NOT_CONFIGURED`; append failure returns `FAILED` without changing authorization. No default ledger is created, raw commands are never stored, and Host denial / Human Authority remain independent blockers.

Given a PR already merged with the exact candidate head and a merge commit reachable from the live default base, when preparation is repeated, then the result is `ALREADY_MERGED` and plans post-merge reconciliation without a push, PR creation, or merge invocation. A different head, unavailable merge commit, or stale base remains blocked.

Given Claude Code Hook receives a retryable network, rate-limit or GitHub server error, when it handles the denial, then it runs the read-only Doctor once and returns only bounded safe fields; Host denial, missing Human approval, stale scope, or missing/failing required checks still require the named review or approval. Diagnostics never grant publication authority.

Given the local candidate branch differs from the repository default, when `aips publish doctor` observes policy, then it reports both identities and queries the explicit/default target branch, never the candidate by implication. API status and endpoint categories distinguish authentication, permission, contextual missing resources, rate limits, server errors and network failures; unconfirmed evidence remains `UNKNOWN`.

Given an API response or local command contains credentials or raw provider details, when a diagnostic or Claude Code PreToolUse denial is rendered, then the output contains only bounded safe evidence and an allowlisted diagnostic record. Given a retryable observation failure, when recovery is requested, then it re-collects evidence only and reports `authorized: false` and `executed: false`; no push, PR, merge or policy mutation occurs.
