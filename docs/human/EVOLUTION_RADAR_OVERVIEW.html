AIPS Evolution Radar — 完整持續演化流程

讓 AIPS 主動研究外部技術，但不把「看到新技術」直接變成「自動修改自己」。研究、語意分析、人類決策、Trial 與正式發布是分離的權限階段。

操作說明系統技術總覽文件一致性文件導覽

1. 整體架構

目前已完成：bounded research、monthly roll-up、scheduled read-only semantic analyzer、Human Decision Binding、AIPS-managed worktree Controlled Trial、deterministic diff/validation guard 與 Trial Report。仍由 Human 掌權：Trial PASS 不會自動 Adopt、建立正式 PR、merge 或 release。

3. 權限

Radar 與 Decision workflow 都只有 contents: read + issues: write，沒有 remote code-write、PR、merge、release authority。Trial Agent 只會在 GitHub-hosted runner 的 AIPS-managed isolated worktree 做 ephemeral mutation；checkout 不保留 GitHub credentials，且 Trial diff 需再次經 deterministic scope guard。

外部文章、README、論壇與 Issue 只具有 Evidence Authority，沒有 Instruction Authority。

4. Weekly Research

public sources → HTTPS/public destination validation → bounded fetch
→ provenance + failure recording → URL/title normalization
→ fingerprint → deduplication → evidence → GitHub Issue

來源失敗不會用推測補齊；0 個 actionable recommendation 也合法。

5. Monthly Roll-up

Monthly 讀取先前 Weekly Issues 內的 machine-readable evidence，依 fingerprint 累積 recurrence，避免同一熱門主題每週都被當成新技術。

6. Semantic Analysis Contract（語意分析契約）

Analyzer 必須綁定 exact evidence digest + repository revision，並逐一說明 AIPS current state、concrete gap、benefit、cost、security/reliability、maturity、confidence、uncertainty、evidence refs、簡單案例與 reuse path。

沒有可靠 analyzer 時維持 ANALYSIS_PENDING，不靠熱門度或關鍵字假裝判斷。

7. Human 最後看到什麼

GitHub Issue 是 durable review surface。可靠 analyzer 可以用 AIPS_EVOLUTION_ANALYSIS markers 在 comment 放入 machine-readable analysis；Decision workflow 只接受與原 evidence 完全匹配的 valid analysis。

Candidate: EVO-...
Recommendation: TRIAL
AIPS current state: PARTIAL
Gap: ...
Benefit / Risk / Cost / Maturity: ...
Example: ...
Human chooses: REJECT / HOLD / ASSESS / TRIAL / ADOPT

8. Human 如何批准

Human 執行 evolution-decision workflow，指定 Issue、signal fingerprint、decision、reason；TRIAL / ADOPT 必須填 approved scope，TRIAL 另外必須填 repository-relative approved path globs。Decision 綁定 evidence digest、baseline revision、actor、time、approved paths 與 decision fingerprint。

如果 baseline 已 STALE，ASSESS / TRIAL / ADOPT 會 fail closed。Human 可明確 override advisory state，但 reason 必須以 override: 開頭留下 audit evidence。

9. 批准後如何推進

Decisionnext action
REJECTclose_candidate
HOLDcontinue_monitoring
ASSESSsystem_improvement_review
TRIALcontrolled_trial_execution → isolated worktree → Trial Report
ADOPTsystem_improvement_review

之後仍走 System Self-Improvement → Core/Constitution Gate（適用時）→ implementation → tests/review → Documentation Consistency → Git Publish Proposal → Human publication approval → PR/merge/release。

10. Controlled Trial 如何安全自動執行

Human chooses TRIAL
→ approved_scope + approved_paths
→ Decision fingerprint + CURRENT baseline validation
→ Execution Isolation: worktree only
→ Codex Action (:workspace, drop-sudo, pinned version)
→ smallest reversible prototype
→ deterministic evaluation
   ├─ actual paths ⊆ approved paths
   ├─ forbidden governance/release paths untouched
   ├─ changed-file / diff-line limits
   ├─ no commit created by Trial Agent
   └─ repository validation PASS
→ Trial Report Issue comment
→ Human chooses Reject / Hold / Adopt
若 OPENAI_API_KEY 未設定、worktree isolation 不可用、Agent 執行失敗或 deterministic validation 不通過，Trial 會回報 BLOCKED/FAIL，不會降級到 shared workspace，也不會把 prototype 推到 remote。

11. Trial → ADOPT Evidence Binding

PASS Trial 不會自動採用。Human 另外選擇 ADOPT 時，可輸入該 Trial Report 的 exact trial_fingerprint。系統只在同一 Radar Issue 找到唯一合法 PASS Trial，且 candidate、signal、baseline 全部匹配時，才產生 Trial-backed ADOPT artifact；artifact 的 next action 仍只是 system_improvement_review。

直接 ADOPT 仍允許，但沒有 PASS Trial fingerprint 時不會被標示成 Trial-backed adoption；任何 ADOPT 都不等於 code publication authority。

12. 文件如何同步
