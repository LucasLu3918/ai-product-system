AIPS Evolution Radar — 完整持續演化流程

讓 AIPS 主動研究外部技術，但不把「看到新技術」直接變成「自動修改自己」。研究、語意分析、人類決策、Trial 與正式發布是分離的權限階段。

1. 整體架構

目前已完成：bounded research、monthly roll-up、scheduled read-only semantic analyzer、Human Decision Binding、AIPS-managed worktree Controlled Trial、deterministic diff/validation guard 與 Trial Report。仍由 Human 掌權：Trial PASS 不會自動 Adopt、建立正式 PR、merge 或 release。

3. 權限

Radar 與 Decision workflow 都只有 contents: read + issues: write，沒有 remote code-write、PR、merge、release authority。Trial Agent 只會在 GitHub-hosted runner 的 AIPS-managed isolated worktree 做 ephemeral mutation；checkout 不保留 GitHub credentials，且 Trial diff 需再次經 deterministic scope guard。

外部文章、README、論壇與 Issue 只具有 Evidence Authority，沒有 Instruction Authority。

4. Weekly Technology Intelligence

6 community + primary sources → public HTTPS validation
→ per-source ≤ 8 → round-robin global raw ≤ 50
→ provenance / source roles → normalization + dedup
→ deterministic shortlist ≤ 12 → semantic queue ≤ 10
→ actionable semantic recommendations ≤ 5 → GitHub Issue

健康門檻是至少 5 個 community sources 成功。來源失敗不會用推測補齊；community-only evidence 不可直接 ADOPT；未進 semantic queue 的 signal 保持 ANALYSIS_PENDING。

5. Monthly Roll-up

Monthly 讀取先前 Weekly Issues 內的 machine-readable evidence，依 fingerprint 累積 recurrence，避免同一熱門主題每週都被當成新技術。

6. Semantic Analysis Contract（語意分析契約）

Analyzer 必須綁定 exact evidence digest + repository revision，並逐一說明 AIPS current state、concrete gap、benefit、cost、security/reliability、maturity、confidence、uncertainty、evidence refs、簡單案例與 reuse path。

沒有可靠 analyzer 時維持 ANALYSIS_PENDING，不靠熱門度或關鍵字假裝判斷。

7. Human 最後看到什麼

GitHub Issue 是 durable review surface。可靠 analyzer 可以用 AIPS_EVOLUTION_ANALYSIS markers 在 comment 放入 machine-readable analysis；Decision workflow 只接受與原 evidence 完全匹配的 valid analysis。

Candidate: EVO-...

8. Human 如何批准

Human 執行 evolution-decision workflow，指定 Issue、signal fingerprint、decision、reason；TRIAL / ADOPT 必須填 approved scope，TRIAL 另外必須填 repository-relative approved path globs。Decision 綁定 evidence digest、baseline revision、actor、time、approved paths 與 decision fingerprint。

如果 baseline 已 STALE，ASSESS / TRIAL / ADOPT 會 fail closed。Human 可明確 override advisory state，但 reason 必須以 override: 開頭留下 audit evidence。

10. Controlled Trial 如何安全自動執行

Human chooses TRIAL
→ approved_scope + approved_paths
→ Decision fingerprint + CURRENT baseline validation
→ Execution Isolation: worktree only
→ Codex Action (:workspace, drop-sudo, pinned version)
→ smallest reversible prototype
→ deterministic evaluation
   ├─ actual paths ⊆ approved paths
   ├─ forbidden governance/release paths untouched
   ├─ changed-file / diff-line limits
   ├─ no commit created by Trial Agent
   └─ repository validation PASS
→ Trial Report Issue comment
→ Human chooses Reject / Hold / Adopt
若 OPENAI_API_KEY 未設定、worktree isolation 不可用、Agent 執行失敗或 deterministic validation 不通過，Trial 會回報 BLOCKED/FAIL，不會降級到 shared workspace，也不會把 prototype 推到 remote。

11. Trial → ADOPT Evidence Binding

PASS Trial 不會自動採用。Human 另外選擇 ADOPT 時，可輸入該 Trial Report 的 exact trial_fingerprint。系統只在同一 Radar Issue 找到唯一合法 PASS Trial，且 candidate、signal、baseline 全部匹配時，才產生 Trial-backed ADOPT artifact；artifact 的 next action 仍只是 system_improvement_review。

直接 ADOPT 仍允許，但沒有 PASS Trial fingerprint 時不會被標示成 Trial-backed adoption；任何 ADOPT 都不等於 code publication authority。

12. 文件如何同步

Evolution Radar scripts/config/templates/workflows/references 改變時，Documentation Consistency Contract 要求 docs/human/EVOLUTION_RADAR.md、本 HTML、orchestration/EVOLUTION_RADAR.md 與技術面變更所需的 docs/human/TECHNOLOGY_GUIDE.html 同步更新。

Optional External Agent / Provider Credentials

AIPS does not require external Agent/provider credentials for normal operation. Credential-dependent enhancements stay disabled until their credential is explicitly configured.

For Gemini provider-session verification, a missing GEMINI_API_KEY is SKIPPED_NOT_CONFIGURED, not a release blocker. Existing verified Gemini CLI runtime and AfterTool capture capabilities remain unchanged.

No OAuth, Vertex AI, GitHub OIDC / Workload Identity Federation, or other replacement login flow is introduced by this policy.

Scenario 145 — External Credential Dependency Guard

AIPS 以 source-controlled registry + deterministic audit 管理外部 Agent/provider credential dependency。未登記 Key/consumer、baseline/release 必要化、pull-request secret exposure 都會 BLOCK repository validation。

Evolution Radar 沒有 external semantic credential 時仍照常產生 research evidence 與 provider-neutral handoff；Retrieval local/default lane 不取得 OPENAI_API_KEY。

Evolution Radar 季度決定性檢視

季度層每年 1／4／7／10 月第一天檢視上一季，只聚合既有 monthly durable evidence，不重新抓取外部來源。它綁定季度與三個月份、累積 signal recurrence，並把季度 recommendation 保持為 ANALYSIS_PENDING，避免 deterministic rollup 冒充新的語意採用判斷。

此流程不需要外部 Agent/provider key、不新增來源 network collection，也沒有自動改碼、implementation PR、merge、release 或 publication authority。

Scenario 152 — Technology Intelligence Expansion

Weekly Radar 使用 50 → 12 → 10 → 5 funnel：最多 50 raw signals、12 Human shortlist、10 semantic candidates、5 actionable recommendations。

Community pool 包含 Hacker News、Lobsters、DEV Community、Stack Overflow、Software Engineering Stack Exchange 與 best-effort Reddit r/programming；GitHub / Cloudflare / Google Developers / Hugging Face 保留為 primary evidence lane。

Forum ≠ adoption authority：community-only evidence 標記為 DISCOVERY_ONLY，沒有 primary-source corroboration 時不能直接 ADOPT。未進 semantic queue 的項目保持 ANALYSIS_PENDING。

Scenario 153 — Evidence Quality & Primary-source Corroboration

Radar 將 discovery popularity 與 technical verification 分離，依 exact source provenance 產生 Level 0–4 deterministic evidence strength。Level 0/1 只有 community evidence；Level 2 起至少有 primary source；Level 3 為 primary + community corroboration；Level 4 為多個 independent primary sources。

ADOPT floor：advisory ADOPT 至少需要 evidence level 2。Semantic provider 不能捏造或提升 evidence level；Monthly / Quarterly rollup 也必須保留來源 counts 與 evidence metadata。這不授權 Trial、implementation、PR、merge 或 release。
