AIPS 系統技術總覽

給 Human / Maintainer 的一頁式技術說明：整理 AI Product System（AIPS）目前導入的重要架構方法、工程技術、治理概念，以及中英文專有名詞、用途與常見情境。

維護規則：設定範圍內的 technical implementation / contract 發生變更時，Repository Validation 會要求本頁同步 review / update。

文件導覽架構總覽Evolution Radar文件一致性

1. 技術定位

AIPS 不是單一 Agent Framework，也不是 Prompt 集合；它比較接近 AI Software Delivery Operating System（AI 軟體交付作業系統），把 Agent 上下文、專案理解、變更治理、驗證、安全、隔離執行、產品交付與持續演化放在同一套 contract 中。

2. Turn-Aware Global Harness（回合感知全域代理框架）

每個 Turn 只載入必要規則與 context，不把整個 AIPS 一次塞入 Prompt。Runtime Adapter（執行環境配接器）負責 Codex、Claude Code、Gemini CLI 等不同 Runtime 的能力差異。

情境

同一套治理要跨多種 Agent Runtime 使用。

Human Harness · Agent Protocol

3. Progressive Disclosure / Lazy Context Loading（漸進揭露／延遲上下文載入）

先載最小核心，再依任務載入 Role、Skill、Project Intelligence 與治理規則，降低 Token 與資訊干擾。

案例

只改 Go API 時，不預載品牌設計與完整產品交付文件。

4. Project Intelligence（專案智慧）

把 Architecture、Data Flow、Module、Contract、DB、Event、Convention、Tests、Security 等理解整理成可重用結構，避免每次重新掃描整個 brownfield repository。

Human 說明

5. Canonical Project Identity（標準專案身分識別）

以 repository_id 表示 repository lineage，以 workspace_id 區分 main / feature / AIPS worktree，讓 Run State、Intelligence 與 Single Writer 能正確作用。

6. Change Impact Guard（變更影響防護）

修改前建立 Change Boundary / Impact Graph，完成後比對 Actual Diff。若實際修改超出批准範圍，必須重新評估而不是默默擴張。

7. Enforceable Governance（可執行治理）

Human Approval 可轉為 machine-readable Approval Record 與 scope fingerprint；若目前操作與批准不再一致，產生 APPROVAL_STALE 並停止。

Approval Binding 批准綁定Stop-the-Line 停線

8. Durable Run State（可持久化執行狀態）

CHECKPOINT.yaml + EVENTS.jsonl 保存結構化狀態；新 session 先判斷 workspace fingerprint 是 CURRENT 還是 STALE。它不保存私人 Chain-of-Thought。

9. Scenario Conformance（情境符合性驗證）

Acceptance Scenario 明確分類為 deterministic / lifecycle / agent_eval / manual / uncovered，不用「檔案存在」假裝已自動驗證。

Human Conformance

10. Agent Evaluation / Agent Eval（代理評估）

語意行為使用 provider-neutral Case / Result / fingerprint；只保存 observable result，不保存 Chain-of-Thought。

11. Execution Isolation（執行隔離）

明確區分 shared workspace、Git worktree 與 verified sandbox。Temporary directory 不會被假裝成 sandbox。

12. Deterministic Automation（決定性自動化）

能用 hash、schema、diff、固定規則驗證的工作交給 Python；真正需要判斷的新技術適配才交給 semantic reasoning。

12A. Deterministic Scheduler（決定性排程器）

LLM/Orchestrator 先完成一次語意規劃並輸出 Structured Task Graph；之後 dependency readiness、stable order、parallel slot 與 Change Boundary lock 由 deterministic code 執行。相同 graph + state 會得到相同 dispatch fingerprint，blocked graph 不會交給 LLM 猜測繞過。

情境

三個 Agent 分別修改不重疊模組時可在 worktree 平行執行；若 boundary 有祖先/子路徑重疊，Scheduler 會自動序列化。

12B. Integration Gate / Janitor（整合候選看門人）

Merge 前把 exact base/head SHA、changed-file hash、Validation Profile 與適用的 Core Change Test Matrix 綁成 candidate fingerprint，再執行專案原生 lint/type/test/security/repository checks。Candidate 變更後舊 PASS 自動失去代表性。

GitHub CI

janitor 先執行，既有 required repository 只在 Janitor success 後成功；PASS 是驗證證據，不是 merge/release 授權。

13. Security Assurance Level / SAL（安全保證等級）

依 Change Boundary 與 protected assets 調整安全保證深度，涵蓋 Secret Handling、Threat Modeling、Authorization、Business Logic Abuse 與 Security Testing。

Security Assurance

14. Product Delivery Lifecycle（產品交付生命週期）

完整產品可停在 LOCAL_COMPLETE；Production 在已要求/批准時才進 Production Enablement、Release Readiness、部署與 post-deploy verification，最後才是 PRODUCTION_VERIFIED。

15. GitHub Actions CI（持續整合）

Repository validation 自動跑在 Pull Request 更新與 main push，需要時可用 workflow_dispatch 手動驗證；standalone feature branch 的每次 push 不再自動跑完整 validation。相同 PR / ref 使用 concurrency cancellation，較新的 run 會取代仍在執行的舊 run。

CI 先執行 janitor exact-candidate Integration Gate，再由既有 required repository aggregate 接收結果；因此 lint/type/test 或 candidate binding 失敗會在 merge 前被擋下。

多檔案工程變更預設先組成完整 logical change，再一次更新 remote branch/ref，避免 file-by-file intermediate commits 觸發大量暫時性 failure 與通知信。Actions 仍使用 immutable full SHA pinning、least privilege，真正的 PR/main failure 通知保留。

16. YAML Contracts / Schemas（YAML 契約與結構）

Approval、Intelligence、Execution Profile、Quality、Delivery、Evolution Evidence / Analysis / Decision 都使用 Human-readable + machine-validatable YAML。

17. Mermaid + SVG / Inline SVG（架構圖）

詳細架構使用 source-controlled Mermaid；Human overview 使用 SVG / inline SVG。圖示屬於 Documentation Impact，而非純裝飾。

18. Evolution Radar（持續演化雷達）

定期收集公開技術訊號，做 provenance、normalization、deduplication、monthly recurrence，再交給可靠 semantic analyzer 與 Human 決策。

完整圖解

19. Scheduled Semantic Analyzer（排程式語意分析器）

Evolution Radar 在有安全 provider credential 時使用 pinned openai/codex-action + pinned Codex CLI，以 :read-only permission profile 對 evidence 與 current AIPS 做語意比較。Model 只輸出 recommendation payload；baseline、digest、provider metadata 與 authority=false 由 deterministic Python 綁定。缺少 credential 或輸出驗證失敗時保持 ANALYSIS_PENDING。

情境

每週技術雷達需要判斷某個外部概念是 AIPS 已覆蓋、應 HOLD，或值得進一步 TRIAL。

20. Human Decision Binding（人類決策綁定）

決策綁定 signal fingerprint、evidence digest、repository revision、scope、actor 與 decision fingerprint；TRIAL 另外綁定 approved path globs。STALE baseline 的正向推進 fail closed。Decision 不等於 code publication authority。

21. Controlled Trial Automation（受控實驗自動化）

Human 核准 TRIAL 後，AIPS 建立 managed Git worktree，使用 Codex :workspace 做 ephemeral prototype，再以 deterministic guard 檢查 approved paths、forbidden paths、diff limits、no-commit 與 repository validation。Prototype 不 push，Trial Report 回到原 Radar Issue，之後仍需 Human Adoption Decision。

情境

想驗證一項架構技術能否改善 AIPS，但不希望研究 Agent 直接建立正式 PR 或改 main。

22. Trial-to-ADOPT Evidence Binding（實驗採用證據綁定）

Human 依 PASS Trial 決定 ADOPT 時，可將 exact trial_fingerprint 與新的 ADOPT Decision 綁定。Deterministic validator 會確認 Trial 唯一存在、狀態 PASS、Candidate / Signal / Baseline 一致，再 handoff 到既有 System Self-Improvement；不因此取得 code-write、PR、merge 或 release 權限。

情境

想明確證明某個正式採用方向，是根據哪一次受控實驗結果做出的 Human 決策。

23. Documentation Consistency Contract（文件一致性契約）

Git changed paths 若命中 behavior-bearing technical rule，CI 要求對應 Human / Agent docs 與本 Technology Guide 同步更新。

完整說明

24. Human Documentation Namespace（人類文件命名空間）

永久 Human-only 文件統一放在 docs/human/；shared canonical technical source 才能留在 docs/ allowlist。獨立 Human artifact 若必須持久存在其他位置，需在 audience registry 明確登記並使用 HUMAN_ prefix。CI 同時掃描 legacy Human path，避免搬移後留下過時導向。

25. Retrieval Intelligence / Hybrid Retrieval（檢索智慧／混合檢索）

Project Intelligence 保留穩定 Architecture、Impact Graph、Source Registry 與 Human-approved Overrides；每個工程 Turn 再透過可重建的本機 SQLite index，組合 lexical search、symbol、bounded structural relation、test、Impact Graph 與 Git history evidence，經 ranking 與 token budget 後只送入當下需要的 Context。Embedding / Semantic provider 是 optional enhancement，未設定時誠實標記 NOT_CONFIGURED，不影響 deterministic/local fallback。

情境

修改退款 retry 時，只帶入 refund implementation、相關 tests 與過去 retry fix commit，而不是載入整個 orders 目錄。

26. Retrieval Quality Evaluation（檢索品質評估）

在導入 Embedding、Vector DB、Tree-sitter/LSP 或 Sourcegraph 前，AIPS 先用 repository-specific suite 比較 v0.20-style static topic context 與目前 local hybrid retrieval。Deterministic metrics 包含 Precision@K、Recall@K、F1@K、MRR、Git-history recall、irrelevant-context rate、direct-source recall delta 與 token usage；latency 僅記錄 observed value，不作共享 CI 的 SLO。

Case 分成 required 與 diagnostic：required 是 release regression gate；diagnostic 是跨語言、low lexical overlap、synonymy、cross-file call chain 等壓力案例，若未達門檻仍保留 FAIL / gap dimension，但不因探索性能力邊界阻擋整體 release。

治理邊界

Benchmark PASS/FAIL / diagnostic gap 都只是 evidence，不會自動啟用 provider、調整 ranking weights 或決定下一個 retrieval technology；後續架構優化仍需 Human review 與既有 System Improvement 流程。

27. Structural Retrieval（結構化關係檢索）

Cross-file candidate 已通過 controlled Trial 與 Human Adoption Decision，現在成為 Retrieval Intelligence 預設 lane。流程為 Exact Symbol → Lexical-index Bridge → Bridge 內其他 Exact Identifier → Indexed Target Definition / Related Test；bridge / identifier / target / test traversal 都有 hard limits 與 truncation telemetry。

邊界

正常 Turn Context 預設啟用；--no-structural 只提供 debug / regression opt-out。採用不新增 Tree-sitter、LSP、Sourcegraph 或 remote provider dependency，也不宣稱 compiler-grade semantic resolution；Scenario 130 仍可 explicit OFF/ON 重播 Trial evidence。

28. Semantic Alias Expansion Candidate Trial（語意別名擴展候選實驗）

AIPS 已完成透明、版本控制的 software-engineering alias expansion Trial；這不是 Embedding，也不宣稱一般語意理解。Full corpus 實測出現 required regressions、registration source-recall regression，且 synonym-access-rotation 沒有 Recall 改善，因此結果為 FAIL / HOLD。

治理邊界

Alias lane 維持 disabled-by-default，semantic.status 仍是 NOT_CONFIGURED，Scenario 132 會重播負向 evidence 並要求 recommendation=HOLD。本結果不會自動啟用 Embedding、Vector DB 或 remote provider；不同 semantic candidate 仍需新的 Human-reviewed Trial。

29. Remote Embedding Retrieval Trial Readiness（遠端嵌入檢索實驗準備）

Alias Trial HOLD 後，AIPS 準備 materially different 的真實 embedding candidate。第一個 adapter 使用 OpenAI v1/embeddings，預設 text-embedding-3-small，但只允許傳送 synthetic Retrieval Quality fixture；AIPS repository / product source transfer 明確禁止。

安全與治理

Credential 只由 protected CI secret 注入；沒有 credential 回 TRIAL_PENDING，provider failure 回 TRIAL_BLOCKED。Request / candidate chunks / remote characters 有 hard limits，向量只在 Trial runtime 記憶體內使用，不導入 Vector DB。正常 Retrieval / Turn Context 不啟用 embedding，PASS 仍需 Human Adoption Decision。

Operator Summary

Dedicated workflow 會把 machine report 轉成 GitHub Job Summary，明確顯示 Trial status、recommendation、provider/model、credential available boolean、privacy scope 與下一步。Workflow SUCCESS 不等於 Trial PASS；Summary 不輸出 credential 值。

30. Provider-Neutral Local-First Embedding Trial（供應者中立／本機優先嵌入實驗）

Scenario 134 將真正 Embedding benchmark 的 default provider 改成本機執行：dedicated Trial 安裝 pinned sentence-transformers，使用 pinned BAAI/bge-small-en-v1.5 revision，在 GitHub Actions runner 內產生 vectors。第一次執行可下載 model artifact，但 query / synthetic fixture 不會送往 embedding inference provider；HF_HUB_DISABLE_TELEMETRY=1。

Remote optional

既有 OpenAI-compatible adapter 不刪除，而是改為顯式 optional provider。只有設定 AIPS_RETRIEVAL_EMBEDDING_PROVIDER=remote 時才需要 OPENAI_API_KEY；預設 local 不需要任何 API credential。兩條路徑都沿用同一 9-case corpus、threshold、required regression gate、ephemeral vectors 與 Human Adoption Decision。

32. v0.27 Reliability Hardening

能力新規則
Evolution Radar Semantic AnalysisOpenAI adapter 改為 optional；沒有 API key 時輸出 provider-neutral handoff，讓 Human-selected Agent / local model 接手，結果仍需 deterministic evidence binding。
Deterministic SchedulerTask 預設視為可能寫入；沒有非空 Change Boundary 直接 BLOCKED。只有 explicit read_only: true 且無 write set 才可 boundary-free。
Integration / Janitor GatePR validation fresh-fetch target branch；declared base 與 current base tip 不一致時 BLOCKED，避免沿用 stale candidate evidence。

三項 hardening 都保留 Protected Human Authority，不新增 Role、Skill 或自動 merge/release 權限。

v0.27 Governance Hardening

Conditional Core Matrix: Large/Core changes and a narrow governance-core Integration Gate safety net require an exact-candidate Core Change Test Matrix; ordinary standard changes remain matrix-optional.

Branch Hygiene: deterministic read-only classification distinguishes persistent operational branches from integrated ephemeral deletion candidates; integration checks use direct ancestry, patch equivalence, then a squash-aware synthetic git merge-tree --write-tree fallback whose tree must equal the target. It never grants deletion authority.

CI de-duplication: focused Scheduler/Integration Gate lifecycle evidence is not executed twice when Janitor already ran it, while standalone repository validation remains complete.

Branch Hygiene Remote Reporting

scripts/branch_hygiene.py supports --remote origin so CI can classify the complete fetched remote branch set instead of only refs/heads from a single-branch checkout. .github/workflows/branch-hygiene.yml refreshes remote refs, emits a deterministic report and Job Summary, and remains strictly report-only with contents: read. Persistent branches and unclassified branches stay protected by policy; a deletion candidate is evidence, not deletion authority.

33. Agent Eval Repeatability / Consistency（代理重跑一致性）

單次 Agent Eval PASS 不再被誤解成穩定性證據。agent_eval.py consistency 可對同一 Case fingerprint 的多次獨立 Result 做 deterministic validation/scoring，輸出 repetition count、PASS rate、outcome consistency、observable-response fingerprint diversity 與 exact response repeatability。

安全與治理

Aggregate report 不保存 response 文字或 private chain-of-thought；stale fingerprint、private reasoning、secret-like values 仍直接視為 invalid evidence。門檻只控制可接受的 rubric PASS rate，不會放寬 evidence validity，也不取得 provider routing、tool-call、merge 或 release authority。

34. Resource-Scoped Agent Authorization（資源範圍代理授權）

Execution Profile 可引用 machine-readable Resource Authorization Profile，把 Agent 權限限制到明確的 resource + ordinary operation。Policy 固定 default_effect: DENY；未宣告資源/operation、缺少必要 Change Boundary、或 profile 嘗試取得 protected authority 時都會 fail closed。

治理與 Enforcement Truth

aips authorization validate/check 產生 deterministic PRE_EXECUTION_EVIDENCE。沒有 verified pre-tool guard 時不宣稱 Runtime 已硬性 enforcement。Profile 不能授權 merge、release、publication、administration、destructive deletion 或 Human approval；credential 只允許 reference，不保存 secret value。

35. Evolution Radar Current-main Baseline / Runtime Security Reassessment

references/evolution/CAPABILITY_MAP.yaml 現在明確索引 Resource-Scoped Agent Authorization，讓語意分析先辨識已覆蓋能力再判斷 gap。Issue #79 的 anomaly / semantic-intent 候選維持 ASSESS-only；anomaly 下一步最多是 bounded evidence Trial，semantic intent 則必須遵守 monotonic authorization，只能縮小或升級審查，不能擴權。

安全邊界

不保存 private chain-of-thought 或 secret values，不自動 remediation，不宣稱 runtime enforcement，不新增 merge/release/publication/Human approval authority。

36. Agent Anomaly Evidence Evaluation（代理異常證據評估）

Scenario 139 建立離線 deterministic benchmark，直接 reuse Resource Authorization 來評估 observable execution event。Detector 只辨識明確可計算的 authorization/policy 違反，不執行 semantic intent 推論。

Metrics

固定 11-case synthetic corpus 產生 TP/FP/TN/FN、precision、recall、FPR、FNR；目前 fixture 為 TP=6、FP=0、TN=5、FN=0。這是 regression evidence，不是 production accuracy 宣稱。

安全邊界

private reasoning / secret-like input fail closed；輸出固定 POST_EXECUTION_EVIDENCE、runtime_enforced=false、critical_path=false、automatic_remediation=false。PASS 只代表 HUMAN_REVIEW_TRIAL_EVIDENCE，不會自動採用或接入 runtime。
