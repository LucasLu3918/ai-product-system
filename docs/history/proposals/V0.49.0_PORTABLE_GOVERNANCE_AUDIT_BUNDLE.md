# v0.49.0 — Portable Governance Audit Bundle

## System Self-Improvement Review

Appropriateness: ADOPT with bounds.

User problem: v0.48 can produce and verify a tamper-evident governance ledger, but a later auditor still needs a portable way to receive the exact ledger anchor, repository revision, public verification keys and supporting evidence digests without trusting an Agent narrative.

Recommended solution: extend the existing governance audit implementation with a deterministic portable bundle and independently distributable anchor.

Reuse: extend scripts/governance_audit.py and orchestration/GOVERNANCE_AUDIT.md; do not add a new Role, Skill, Capability ID or approval gate.

Security boundary:
- baseline bundle creation/verification remains credential-free;
- HMAC material is never persisted in the bundle;
- public verification keys may be copied into the bundle;
- signing private keys, prompts and private reasoning are excluded;
- signed ledger history must verify against supplied public keys before bundling;
- an internal ANCHOR.json is integrity metadata, not an independent external trust anchor; truncation/resubmission resistance requires independently retained/distributed anchor evidence or an equivalent signed checkpoint.

Authority: bundle evidence is downstream of existing Human Approval / Security / Release authority and grants no merge, release, publication or production authority.

Constitution impact: NO.

Architecture Diagram Impact Check: detailed Governance Audit diagrams/docs are affected and will show the bundle/anchor flow. Top-level Human SVG remains accurate because this is an extension of the existing Governance + Evidence topology, not a new subsystem.

## Core Change Scope

In scope:
- bundle-create and bundle-verify commands in the existing audit helper;
- deterministic MANIFEST.json, AUDIT.jsonl and ANCHOR.json bundle format;
- optional independent anchor export;
- repository revision, event count, chain head, evidence-file SHA-256 and public-key fingerprint binding;
- offline verification of ledger, evidence, public keys and external anchor;
- Scenario 159 and deterministic lifecycle evidence;
- synchronized Governance Audit, Security Assurance, Release Readiness, Architecture, Conformance and Technology Guide documentation.

Out of scope:
- blockchain, transparency log, remote timestamping or central audit server;
- automatic GitHub API evidence collection;
- mandatory HMAC/provider credential;
- storage/retention service;
- new governance authority or approval gate.

Migration: additive; v0.48 ledger format remains valid.

Rollback: remove bundle commands/tests/docs while preserving the v0.48 audit ledger.

Human approval: the current request explicitly authorizes implementation and Git publication of the recommended next-version direction without further confirmation.
