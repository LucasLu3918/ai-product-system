# v0.52.0 — MCP Interoperability Gateway

## System Improvement Review

Appropriateness: ADOPT with bounded scope.

User problem: AIPS currently needs runtime-specific integration work to make the same Roles, Skills and deterministic orchestration helpers conveniently available to each new Agent/IDE.

Proposed solution: expose AIPS through a standard MCP server so MCP-compatible hosts can reuse AIPS directly.

Existing coverage: the Global Harness already owns runtime-specific context/enforcement integration; Roles/Skills are canonical indexed files; deterministic AIPS helpers already exist.

Reuse / extension: extend the existing turn-aware Global Harness / harness-runtime surface with an MCP access plane. Do not add a new Capability ID, duplicate Role/Skill bodies, create an MCP-specific reasoning engine, or replace verified runtime-native hooks.

Recommended solution: local stdio MCP Gateway with Resources + Prompts + bounded deterministic Tools. Native adapters remain for TURN_NATIVE / TOOL_GUARDED behavior.

Context/token cost: catalogs are compact; bodies are loaded by resource only after selection. No whole-repository preload is added.

Security / reliability:
- local stdio only;
- project tools are confined to AIPS_MCP_WORKSPACE;
- no external provider credential;
- no LLM call inside the server;
- client registration is review-only, not silently written;
- MCP-only enforcement is truthfully ADVISORY;
- protected operation authority remains false.

Backward compatibility: additive. Existing Codex / Claude Code / Gemini CLI adapters and ordinary AIPS CLI commands keep their behavior.

Scenario/test impact: add Scenario 162 lifecycle coverage, official MCP Client stdio E2E, pinned Codex MCP registration verification and repository contracts.

Human docs impact: README, Harness, Installation, User Guide, Architecture Overview, Conformance and Technology Guide.

Agent docs impact: SYSTEM, Harness Protocol, Adapter Contract, MCP Gateway protocol, Conformance.

Architecture diagram impact:
- docs/ARCHITECTURE.md: AFFECTED — add MCP access plane parallel to native adapter plane.
- docs/human/assets/harness-overview.svg: AFFECTED — show MCP-compatible hosts.
- docs/human/assets/system-overview.svg: AFFECTED — entry plane now includes MCP.
- product-delivery-overview.svg: N/A — delivery lifecycle is unchanged.
- project-intelligence-overview.svg: N/A — Intelligence semantics/storage are unchanged.
- system-lifecycle.svg: N/A — AIPS install/uninstall ownership semantics remain unchanged because v0.52 does not mutate client-owned MCP registration.

Constitution impact: NO.
Why: Human authority, scope integrity, approval semantics and protected Git/release behavior remain unchanged.

## Core Change Scope

In scope:
- official MCP Python SDK v2 dependency;
- local stdio MCP server;
- canonical Role / Skill / selected protocol Resources;
- reusable security / architecture / code review / delivery planning Prompts;
- bounded read-only/deterministic AIPS Tools;
- AIPS_MCP_WORKSPACE confinement;
- inspect + review-only client config CLI;
- Scenario 162 + exact protocol lifecycle;
- pinned Codex MCP registration/list verification;
- architecture/documentation synchronization.

Out of scope:
- remote Streamable HTTP or SSE deployment;
- OAuth / hosted AIPS service;
- provider/model execution inside MCP server;
- automatic Cursor/Codex/client configuration mutation;
- Git push / PR / merge / release / production tools;
- replacing native adapters;
- new Role, Skill, Capability ID or Approval Gate.

Rollback: remove the MCP dependency/gateway/CLI/docs/tests; native Harness adapters and all existing AIPS workflows continue unchanged.
