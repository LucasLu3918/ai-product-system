# v0.53.0 — Human Documentation Site & Installation UX

## System Self-Improvement Review

Problem:
- Human Docs had become append-only in several current-behavior documents.
- standalone HTML accumulated numbering/layout drift and lacked shared navigation/search.
- public install docs still taught manual clone/cd/bootstrap preparation.
- Windows had no explicit supported installation path.

Reuse-first solution:
- docs/human remains the single Human source;
- VitePress is renderer only;
- existing Documentation Sync is extended with deterministic placement validation;
- existing aips install/uninstall remains the lifecycle core;
- new install launchers manage checkout and delegate to the existing lifecycle;
- bootstrap.sh remains backward-compatible only;
- Windows support is truthful WSL-based, not native PowerShell runtime.

Architecture impact: YES.
Constitution impact: NO.
New Role/Skill/Approval Gate: none.
External Agent/provider credential: none.

Docs deployment boundary:
- pull requests build only;
- main may deploy to GitHub Pages;
- docs deployment grants no code merge/release/product production authority.

Human approval: current request explicitly authorizes implementation and Git update flow.

## Validation reconciliation

During exact-candidate validation, normalizing malformed import lines in `tests/validate_repository.py` re-enabled two existing anomaly-evidence contract modules that had unintentionally not executed. The resulting failures exposed two latent defects: an over-escaped secret-detection regular expression and a missing `private_reasoning_paths()` helper used by observable-event validation.

The candidate fixes those defects instead of suppressing the tests. Existing Scenario 139/140 semantics are unchanged; validation now executes the fail-closed secret/private-reasoning checks that the repository already claimed.

Installation lifecycle evidence was also reconciled with the new public-install contract: install now runs runtime dependency checks, static installation integrity, Human-doc placement validation and Harness registration instead of the full developer repository validation suite. Preflight and explicit repository validation still run the full suite where appropriate.
