# Security Policy

## Supported version

Security fixes are applied to the current `main` branch and the latest released version.

## Reporting a vulnerability

Please do not disclose credentials, exploit details, private data, or other sensitive vulnerability information in a public Issue.

If GitHub shows **Report a vulnerability** / private vulnerability reporting for this repository, use that private channel.

If a private repository security channel is not available, contact the maintainer through a private channel they have explicitly published on their GitHub profile or repository metadata. Do not include live secrets in the initial report.

For non-sensitive security hardening suggestions that do not expose an active vulnerability, a normal GitHub Issue is acceptable.

## What to include

Provide only the minimum information needed to reproduce and assess the issue:

- affected AIPS version / commit;
- affected subsystem;
- reproduction steps using non-secret test values;
- expected vs actual behavior;
- impact and known preconditions;
- suggested mitigation if available.

Never include real credentials or private chain-of-thought/model internals.
